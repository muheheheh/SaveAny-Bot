# 使用说明

SaveAny-Bot 可以将 Telegram 媒体自动回传到当前聊天，也可以将 Telegram 或网站上的文件保存到其他存储。完整功能列表见 [项目首页](https://github.com/muheheheh/SaveAny-Bot/blob/main/README.md#支持的功能)。

## 首次使用

1. 使用 `config.docker.example.toml` 模板，在配置中填写 Bot Token 和允许使用机器人的 Telegram 数字用户 ID。
2. 按 [Docker 部署](../deployment/installation.md) 启动机器人。
3. 打开机器人私聊，点击 **Start** 或发送 `/start`，然后发送或转发媒体。

模板没有配置存储，机器人只回传到当前聊天，不需要设置默认存储或开启静默模式。

## Telegram 媒体回传

| 输入方式 | 操作方法 |
| --- | --- |
| 单张图片、视频或文档 | 直接发送或转发给机器人 |
| 相册或媒体组 | 将整组媒体发送或转发给机器人，尽量保留原有分组 |
| Telegram 消息链接 | 发送类似 `https://t.me/channel_username/123` 的链接，机器人读取其中的媒体 |

回传始终开启，目标是发起请求的当前聊天。相册保留顺序，每条消息的说明文字按纯文本保留。

只回传时不下载、不缓存、不重新上传媒体。单文件和相册不发送进度提示；读取消息链接时会显示临时提示，全部回传成功后自动删除。失败或部分失败时保留错误信息，用户原消息和已回传的媒体不会删除。

消息链接需要相应访问权限。启用 UserBot 需要另行登录用户账号，也需要该账号本身能够访问源消息；回传不会绕过 Telegram 的权限或内容保护。

## 保存与任务管理

| 命令 | 作用 |
| --- | --- |
| `/storage` | 设置默认存储 |
| `/silent` | 开启或关闭自动保存 |
| `/task` | 列出正在执行的任务 |
| `/task queued` | 列出排队中的任务 |
| `/cancel <任务ID>` | 取消指定任务，也可点击进度消息上的取消按钮 |
| `/help` | 查看机器人帮助 |

配置存储并授权给用户后，机器人会先回传 Telegram 媒体，再询问保存位置。用 `/storage` 选择默认存储，再用 `/silent` 开启自动保存，可按默认存储及规则处理。`/silent` 是切换开关，再发一次会关闭；这两个设置按用户保存。

下载保存任务保留原有进度和结果。没有可用存储时，媒体回传后即结束；主动执行 `/save` 等保存命令则会提示没有可用存储。网站链接使用对应的解析器或下载器。

`/task` 和 `/cancel` 管理排队或执行中的下载保存任务，直接回传不进入任务队列。

## 其他支持的功能

| 场景 | 操作或前提 | 详细说明 |
| --- | --- | --- |
| 保存已有媒体或历史消息 | 回复媒体发送 `/save`，或使用 `/save <聊天ID或用户名> <起始消息ID>-<结束消息ID> [文本正则]` | 保存到已配置的存储，不额外触发回传 |
| 保存到其他存储 | 配置本地磁盘、S3、MinIO、WebDAV、AList、Rclone 或 Telegram 存储 | [存储端配置](../deployment/configuration/storages.md) |
| HTTP/HTTPS 文件直链 | `/dl <链接1> [链接2]` | [直接下载链接](./directlinks.md) |
| 网站图片和媒体 | 发送 Telegraph 文章链接，或发送 Twitter/X、Kemono 等已启用解析器支持的链接 | [网站解析](./parsers.md) |
| 网站视频与音频 | `/ytdlp <链接> [参数]`，需要安装 yt-dlp，部分处理需要 FFmpeg | [yt-dlp 使用](./ytdlp.md) |
| Aria2 下载 | `/aria2dl <链接>`，需要启用并配置 Aria2 RPC | [Aria2 使用](./aria2.md) |
| 自动选择存储或目录 | 使用 `/rule` 配置规则，使用 `/dir` 管理目录 | [存储规则](./rules.md) |
| 文件命名与重名处理 | `/config`、`/fnametmpl`；快速回传保留原媒体文件名 | [文件命名](./config.md) |
| 存储间传输 | `/transfer`，源存储需支持文件列举和读取 | [存储间传输](./transfer.md) |
| 监听聊天 | `/watch`、`/unwatch`、`/lswatch`，需要启用 UserBot | [监听与通知](./watch.md) |
| 本地文件上传与目录监听 | 在服务器运行 `saveany-bot upload` 或 `saveany-bot watch` | [命令行使用](./cli.md) |
| 程序调用与回调 | 配置 HTTP API，可创建、查询、取消任务并接收 Webhook | [HTTP API](./api.md) |
| 扩展网站支持 | 启用并加载 JavaScript 解析器插件 | [插件开发](https://github.com/muheheheh/SaveAny-Bot/blob/main/plugins/README.md) |

## 回传范围

- 直接发送或转发的 Telegram 媒体、Telegram 媒体消息链接支持回传。
- 同时保存、主动执行保存命令、网站下载和聊天监听仍按原有流程传输文件，可能使用服务器临时目录。
- 保留原媒体类型和文件名，不应用强制文件发送、重命名、转码或分卷；说明文字中的富文本格式不会重建。
- 无法获取或使用媒体引用时，保留回传错误，不会自动下载重传；已配置的保存流程独立执行。
- 纯文本聊天记录、投票等不在媒体回传范围内。
- 配置、会话、用户设置和日志仍属于服务器运行数据。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 提示没有权限 | 检查 `[[users]].id` 是否为发消息的用户数字 ID；修改配置后重启程序 |
| 保存命令提示没有可用存储 | 检查存储已启用，且用户的存储过滤规则允许访问它；只回传无需存储 |
| 每次回传后都要求选择存储 | 需要自动保存时，用 `/storage` 和 `/silent` 设置；只需回传时，将该用户设为 `storages = []`、`blacklist = false` |
| 无法读取消息链接 | 检查链接和访问权限；普通用户能看到的消息不一定对机器人账号可见 |
| 引用发送失败 | 查看错误和日志；确认源媒体仍可访问后重新提交。此模式不会自动下载重试 |
| 服务器出现缓存文件 | 检查是否配置了存储，或执行了保存命令、网站下载、聊天监听等任务；仅回传不会创建媒体缓存 |

更多配置见 [配置说明](../deployment/configuration/_index.md)。反馈问题时，请在 [Issues](https://github.com/muheheheh/SaveAny-Bot/issues) 提供复现步骤和已隐藏 Token 等敏感内容的日志。
